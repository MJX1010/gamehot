## 部署前必读

本 PR 只提供待审查代码，不代表任何现有站点已部署。相对上述 GameHot 基线新增 36 个迁移，包含删列和身份验证变更：

- 后台仅保留管理员密码登录；确认已有 `ADMIN_PASSWORD` 至少 12 位。飞书登录身份列被移除，原飞书登录会话失效，飞书通知功能不受影响。
- 移除 `sources.first_party`，一手标签由 T1 推导；清理 stories/facts/reports/receipts/deliveries 的旧列，不要让旧 API 或 worker 与新 schema 混跑。
- 加入刊号、正文隐藏状态、英文文案与搜索、任务状态及相关索引。
- 种子只插入不存在的信源 ID，不覆盖线上同 ID 的配置；已有数据库与种子并不一定完全一致，部署后应在后台核对实际信源。

完整变更与备份方法见 [部署文档](deploy.md#更新)。在运行实例所在机器操作，先记录当前部署版本并做好数据库和附件备份，验证备份可恢复，再按顺序执行：

```bash
# PR 审核合并后，拉取已审核代码；保留现有 .env，不重跑 init-env
# 先按 docs/deploy.md 备份数据库和 uploads / feedback-screenshots
# 不要直接粘贴升级命令到未备份的生产环境

docker compose build
docker compose stop api worker web
docker compose run --rm setup && docker compose up -d
```

使用 HTTPS profile 的部署保留原有 `--profile https`。setup 失败就停止并检查报错，不跳过迁移、不启动新旧混合服务。worker 正常停止会等待正在进行的调用收尾。数据库发生删列后不能仅切回旧镜像回滚；须结合升级前备份恢复数据库与对应附件。

升级后核验网页、健康检查、管理员密码登录、后台信源和任务状态；只有原有模型与采集配置确实有效时，才验证新内容完整处理链。本次没有读取或修改任何真实密钥，没有访问用户电脑或部署线上服务。
